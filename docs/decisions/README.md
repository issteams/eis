# Architecture Decision Records

Architecture Decision Records (ADRs) capture decisions that constrain or explain the EIS architecture.

## Existing decisions

- [ADR 0001 — Foundation boundaries](0001-foundation-boundaries.md)

## When to add an ADR

Create an ADR when a decision affects a major boundary, public contract, persistence model, provider strategy, execution/security model, or other choice that future maintainers need to understand.

## ADR structure

Use:

1. Context
2. Decision
3. Consequences
4. Alternatives considered
5. Status

An ADR records why a decision was made; it does not replace implementation documentation.
